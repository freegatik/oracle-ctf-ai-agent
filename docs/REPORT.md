# REPORT - Отчёт о выполнении

> Статус: **финальный**. Все траектории собраны, модель дообучена и усилена (v2),
> тесты пройдены, документация актуальна.

## 1. Постановка
Разработан интеллектуальный агент решения CTF-заданий по администрированию Oracle
Database с фиксацией траекторий в стандарте **OpenInference** и интеграцией с реальной
СУБД. Целевой объём - ≥1000 траекторий, включая неудачные попытки.

## 2. Архитектура решения
См. `ARCHITECTURE.md`. Кратко: дообученная LLM-policy (Qwen2.5-Coder-7B, QLoRA) в
ReAct-обёртке, единственный инструмент `execute_sql` к Oracle Free 23ai (Docker),
модуль трассировки на OpenTelemetry + семантика OpenInference.

## 3. Дообучение policy
- База: `mlx-community/Qwen2.5-Coder-7B-Instruct-4bit`, QLoRA (rank 16, 8 слоёв, mask_prompt).
- Датасет: 1000 пар `задание->SQL` (генератор: 13 параметров профиля, размеры/квоты).
- **Две версии:**
 - **v1** - базовый генератор (узкие формулировки). Train loss -> ~0 за ~40 итераций.
 - **v2** - обогащённый генератор (синонимы, разные стили списков, шаблоны блоков).
 Цель - робастность к формулировкам. Адаптер v1 сохранён (`adapters_v1_backup`).

## 4. Окружение СУБД
- Oracle Free 23ai в Docker (ARM64), seed: схема `CTF`, объект `CTF.CTF_FLAG`,
 таблица `credentials`, заблокированный `compromised_user`, привилегированный `dba_ctf`.
- Флаг: `FLAG{0r4cl3_pr1v_3sc_m4st3r}`.

## 5. Агент и траектории
- ReAct-циклы: **one-shot** (генерация->выполнение->коррекция) и **deep** (план->пошагово->
 рефлексия ошибок, с инъекцией конфликтов БД для реальных провалов/восстановлений).
- Формат: OpenInference-span'ы (AGENT/LLM/CHAIN/TOOL) с атрибутами `llm.*`, `tool.*`,
 `input/output.value`, статус success. Strict-экспорт в OTLP (`openinference_otlp.json`).

## 7. Качество и обобщение (тестирование)
| Тест | v1 | v2 |
|------|-----|-----|
| 3 официальных эталона (live Oracle, флаг) | 3/3 | **3/3** |
| Held-out 50 (PDF-стиль): шаги / значения | 100% / 99.7% | **100% / 100%** |
| устойчивость 100 novel (др. формулировки): полностью | 19% | **30%** |
| - обязательные шаги | 67.1% | **85.5%** |
| - точные значения | 70.4% | **96.3%** |
| Рукописные novel (live Oracle, флаг) | 0/3 | **2/3** |
| Компонентные + интеграционные тесты | - | **16 passed** |

**Ключевое наблюдение:** v1 был переобучен на формулировки (held-out 100%, но novel 19%).
Обогащение трейна стилями/синонимами (v2) подняло обобщение (значения 70->96%, live 0/3->2/3)
**без регресса на PDF-стиле** (остался 100%). Это итерация «нашли слабость тестами -> исправили».

**Остаточная слабость:** на экстремальных перефразировках модель изредка роняет шаг
(напр. `GRANT CREATE SESSION`) -> ~14% пропуск шагов. На стиле Примеры.pdf не проявляется.

## 8. Производительность
- Решение одной задачи (greedy, one-shot): генерация ~10-13 s + выполнение в Oracle ~0.4 s
 = **~12-16 s задача->флаг**.
- Разовая загрузка модели ~30-60 s (прогреть до демо).

## 9. Выводы
- Связка дообученная-Qwen + ReAct + реальная Oracle решает целевые задания (3/3, 99.9%).
- Траектории соответствуют OpenInference, экспортируются в OTLP, ингестятся в Phoenix.
- Тестирование вскрыло и закрыло реальную слабость обобщения (v1->v2).
- Модуль готов к интеграции с СУБД (env-конфигурация соединения).
