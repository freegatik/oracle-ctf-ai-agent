# DIARY - Журнал работ

## 2026-06-11

**Анализ задания.** Разобраны `Примеры.pdf` (3 варианта) и методички
(Аутентификация / Профили / Авторизация). Установлено: CTF - это серия задач
администрирования Oracle (tablespace, profile, role, user, привилегии, флаг),
а не классический pwn/web/crypto. Формат жёсткий, 8 шагов.

**Выбор модели.** M4 Pro 24 GB. Для генерации Oracle SQL из русского текста выбран
`Qwen2.5-Coder-7B-Instruct-4bit` (code-специализация). QLoRA через mlx-lm - нативно
для Apple Silicon, влезает с запасом (peak ~6.3 GB при обучении).

**Окружение.** Системный Python 3.14 без MLX-wheels -> создан venv на 3.13.
Установлен mlx-lm 0.31.3.

**Датасет.** Написан генератор `scripts/generate_dataset.py`: пул из 13 параметров
профиля с диапазонами и 2-4 перефразировками каждого пункта; размеры tablespace и
квоты варьируются. 3 официальных варианта зашиты явно. Сгенерировано 1000 примеров
(chat-формат, `mask_prompt`). Проверено: SQL для Варианта 1 совпал с PDF.

**Обучение.** Загрузка модели с HF зависала (unauthenticated rate-limit) - перешёл на
`hf_transfer` с resume, докачал 4.1 GB. QLoRA: train loss 0.174->0.002 за 40 итераций,
val loss ~0. Остановлено на iter ~300 (сошлось, дальше смысла нет). Адаптер сохранён.

**Пивот по ТЗ.** Уточнено реальное ТЗ: нужен не просто fine-tune, а **агент** с
модулем фиксации траекторий (**OpenInference**), интеграцией с **СУБД** и файлом из
**≥1000 траекторий** (вкл. неудачные). Файлы товарища `ep_*.json` - это эти траектории.

**СУБД.** Поднят Oracle Free 23ai в Docker (`gvenzl/oracle-free:slim`, ARM64). Seed:
схема CTF + флаг, таблица credentials, заблокированный compromised_user, dba_ctf (DBA).
Проверено соединение через `python-oracledb`.

**Агент.** Реализованы `agent/{config,oracle_tool,llm,tracing,agent}.py`. ReAct-цикл:
генерация SQL -> выполнение пооператорно -> наблюдение -> коррекция по ORA-ошибкам ->
финальное чтение флага под CTF_STUDENT. Траектории пишутся в OpenInference (spans
AGENT/LLM/TOOL -> `ep_*.json`).

**Отладка.** Первый прогон: ORA-00942 на чтении флага - фильтр ошибочно пропускал
`GRANT SELECT ON CTF.CTF_FLAG`. Исправлено (фильтровать только финальный SELECT и
SET ROLE). После фикса: 3/3 официальных варианта - success, флаг получен.

**Скорость.** Замер: генерация ~23 s (модель упиралась в max_tokens=1000, выдавала
~3669 символов мусора за решением). Снижен `max_tokens` до 600; добавлен sampling
(temp 0.3) для естественных провалов в части прогонов. Сбор 1010 траекторий ≈7 ч -
принято как приемлемое (сопоставимо с временем товарища).

**Документация.** Созданы PROJECT / PLAN / ARCHITECTURE / DIARY / CHANGELOG / REPORT.

## 2026-06-12

**Сбор завершён.** one-shot 1010 (1009 ok / 1 fail; единственный fail - битый
`PASSWORD_REUSE_MAX` под temp + утечка спецтокена `<|im_end|>`). deep ReAct 500
(425 ok / 75 fail) с планом, рефлексией ошибок и инъекцией конфликтов БД (5 типов).
Итого **1510 траекторий**, 1434 ok / 76 fail. Провалы намеренные - закрывают ТЗ
«включая неудачные».

**Strict OpenInference.** `export_openinference.py` -> каноничный OTLP (22502 span'а).
Phoenix поднят отдельным сервером (`phoenix serve`; in-process launch_app не успевал
стартовать под нагрузкой), ingestion через OTLP-пайплайн подтверждён.

**Тесты.** 16 тестов (11 компонентных + 5 интеграционных Oracle, read-only чтобы не
мешать сбору). pytest-cov. Демо-ассеты: `demo.py` (live задача->флаг по шагам),
`pick_showcase.py`, `verify_phoenix.py`, `finalize.sh`.

**Честное тестирование вскрыло слабость.** held-out (PDF-стиль) 100%, НО устойчивость на
100 novel-формулировках - лишь **19%**, 3 рукописные задачи в live Oracle - **0/3** флага.
Вывод: модель v1 переобучена на ДОСЛОВНЫЕ фразы (mask_prompt -> loss только по SQL ->
не показывал проблему). Зубрила «фраза->параметр», на синонимах ломалась.

**Усиление (v2).** `phrasings_aug.py`: обогатил трейн синонимами, стилями списков
(-/нумерация/тире/в строку), вариативными шаблонами блоков. SQL-цели не трогал. v1
забэкаплен. Переобучил v2.

**Результат v2 (до->после):** novel полностью 19->30%, шаги 67->85%, **значения 70->96%**,
рукописные live **0/3->2/3**. PDF-стиль held-out остался **100%** (без регресса), 3/3
эталона. Принято решение коммитить v2. Остаток: на диких перефразировках изредка роняет
шаг (`GRANT CREATE SESSION`) - на стиле PDF не проявляется, риск на защите низкий.
